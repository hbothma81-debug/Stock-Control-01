## Checking what is live

- `node CHECK-what-is-live.cjs "text"` — pass text that exists only in the new build, each as its own argument (plain text, not a pattern). The build strips comments and renames code, so a comment-only or behaviour-only change has to be checked by reading the deployed code. It matches capitals exactly: text a PDF prints in capitals is written in capitals in the code ("DRAW FROM STORES"). A style-only change is found by its style's name (`reqActionBtnAlertOn`): the keys of `S` survive the build.
- A change with no new words on screen (who sees a control, a rule) is proven live by waiting for the bundle's name to change (`CHECK-what-is-live.cjs` prints it as "Live now: App-….js") and then searching the downloaded bundle with a pattern that survives the build: property names and quoted strings do (`isAdmin\?\w+:"newest"`), variable names do not. A commit that puts a file back exactly as an earlier commit had it builds to that earlier bundle's name again (App-r5kOsneM.js on 17 and 18 Sep), which is its own proof. Live's bundle name is never the local build's name for the same commit (19 Sep 2026: App-DLey-lHp.js live, App-DrI4FfZ5.js local), so write down the name that is live before pushing, or the new build already being up reads as "still the old one". The live page's own HTML names only `assets/index-….js`; the App bundle's name is inside that file, which is why the script is used and not a grep of the page.
- `node CHECK-live-table.cjs table` — whether a table answers on live. A column can be checked the same way without signing in (`"job_quote_items?select=extra_stages"`): selecting it answers 200 if it exists, 400 if not, and the script says NO with the database's own message. Until 21 Sep 2026 the script added `?select=*` to a column check as well, a broken address that answered 400 whether the column existed or not: every "400, column missing" reading on live before that date proves nothing. When a check matters, run it beside a column known to exist and one made up.
- A row count cannot be read without signing in: the public key sees no rows, so every count through it reads 0. Counts come from a `CHECK-*.sql` pasted on live (`CHECK-production-queue-size.sql` shows how close the Production tab's loads are to both limits under "Loading data").
- `node CHECK-undefined-names.cjs` after every change — a missing name blanks the whole app even though the build passes.
- Run `git log --oneline origin/main..HEAD` as its own step and read the answer before pushing. Never chain the check and the push in one command. Print the live tip (`git log --oneline -1 origin/main`, after `git fetch`) as the first line of that step and compare it with the last push Planning made: on 17 Sep another conversation had pushed the whole branch twice, 27 commits, and only that line showed it. `git reflog show origin/main` dates every push seen from this folder. If it moved: list what went live, tell me, and health-check exactly that commit (clean clone: build, tests, names; the live page loads with no console errors).
- One commit live ahead of an unreviewed queue, without rewriting the shared branch: in a scratch clone `git checkout -B x <live sha>` and `git cherry-pick <mine>`; build, test and names there; `git fetch <clone> x:x` into this repo; `git log origin/main..x` as its own step (exactly the one commit); `git push origin x:main`; then `git merge origin/main` on the shared branch (the same change on both sides merges clean) and delete `x`. Where live's `CLAUDE.md` differs, leave it out of the cherry-pick (`-n`, then `git checkout HEAD -- CLAUDE.md`). Never rebase the shared branch.
- `npm test` runs Node's own test runner over `src/**/*.test.js`: the shift-window and cutting-time sums, the nesting-report parser, the job sheet's stock grouping and more. No database, a second to run.
- `CHECK-job-stuck-on-packing.sql` (change the job number on its third line) shows a stuck job's stages, each line with whether the packing stage counts it and how many are packed, and its laser programs. A job with every part packed can still be held by one program never ticked cut: the Laser stage closes only when Nesting is ticked and every program is cut, and every stage after it waits.

## Gotchas in App.jsx (each one passed a clean build)

- A component declared inside `App()` remounts on every render and throws the cursor out of text boxes. Render with a plain function instead.
- `isAdmin || cond && <x/>` shows nothing to admins. Bracket it: `(isAdmin || cond) && <x/>`.
- A helper handed to something declared higher up in the file must be a `function` declaration, not a `const`.
- Counting inside a state updater and reading the count on the next line gives 0.
- The PDF's standard fonts cannot print arrows such as `↳`; the whole line comes out letter-spaced.
- `stageIsCleared` is the one test for "this stage no longer holds the next one back", shared by `blockingStages` and `itemFlowLimit`. They used to disagree. Never write the condition out a second time.
- The packing screen passes no `limitFor` on purpose. Capping the packer by `itemFlowLimit` would zero his counts for jobs whose sheets are still being cut, which the first-sheet rule exists to give him. Change the two together or not at all.
- Two `setForm({ ...form, x })` calls in one handler keep only the last: both spread the same stale `form`. Use `setForm((f) => ...)`, or queue the second change through an effect as `LibraryField` does.
- A suggestion list positioned inside its parent is cut off by any scrolling pop-up around it (`S.modal` scrolls). `TypeToFind` pins its list to the viewport for this reason; do not hand-roll another one.
- Tapping a suggestion fires mousedown, then the input blurs. The blur handler must not act on the typed text again, or the tap is overwritten.
- Mixing `padding` from `S.input` with a `paddingRight` override makes React drop one of them with a console warning. Override the whole `padding`.
- A `TypeToFind` given its own `padding` in `inputStyle` also needs `boxSizing: "border-box"`, or the box grows past its wrapper by the padding and covers whatever sits beside it (the Then box hid its None button by 32px).
- A PDF table with no `styles` prints at 10pt, bigger than the sheet's body text. Take every size from one scale at the top of the function, as `printJobSheet` does.
- A script that patches App.jsx must demand exactly one match per edit and refuse to write otherwise. A shorter indent is a substring of a longer one, so a loose pattern edits the wrong place. A check for "a second copy further on" must start looking past the whole first match: a pattern that begins with its indent is found again ten characters in, inside itself.
- `consumeProgramStock` (a tube cut moving stock) repeats `useAllocation`'s steps: the shelf, the reservation, the usage log. Change one, change the other.
- When a form's fields move to another screen, move its checks with them. New Job kept "select at least one process" after the stage ticks left it, and blocked every new job on live.
- A box that saves on blur with `defaultValue` keeps showing its old text after somebody else changes the stored value, and writes it back on the next blur. Give it `key={storedValue ?? "blank"}` so it is rebuilt when the stored value changes (the laser priority boxes do).
- A `type="number"` box reports `""` for text it cannot read ("1e", "--"), which a save-on-blur takes for "clear it". Return early when `e.target.validity.badInput` is true.
- A re-cut row on the laser screens carries `process: null` (the shortage rows in `useLaserPrograms.js`). Anything drawn from `r.process` must allow for none: opening a tube re-cut on Tube Laser > Nesting handed it to `QtyProgressControl` and blanked the whole app until 16 Sep. Nothing in the app catches a render error.
- Saving several rows in one `insert([...])` sends every key any row has, and a row without that key saves null, not the column's default. A not-null column then refuses the whole batch: Copy job could not copy a job with tube material on only some lines. Give every row every key, or leave the key off every row. To tell whether a column exists, read a row with `select("*")` and check its keys (`submitCopyJob`).
- A row drawer that takes an optional second value (`renderJobRow(job, atStage)`) must never be handed straight to `.map`: map passes the position as the second value, row 0 draws and row 1 blanks the app. Write `.map((j) => renderJobRow(j))`.
- App.jsx holds four literal NUL characters (in the `idFor(...)` strings of `saveMasterToTables`, about line 2790). The app runs, but the Grep tool (ripgrep) takes the file for binary from there and silently reports nothing after that line. Until they are written as `\0` (same ids), search App.jsx with PowerShell `Select-String` or a node script. Check with a byte count, not by eye.
